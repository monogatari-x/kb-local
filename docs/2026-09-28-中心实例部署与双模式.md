# 中心实例部署与双模式架构(2026-09-28)

## 双模式

kb-local 支持两种部署模式,**互不冲突**,按需选择或并存:

| | ① 单人模式(现有) | ② 多人模式(中心实例) |
|---|---|---|
| 部署 | 每人本机跑一份 | 192.168.0.10 一份,大家连 |
| 数据源 | 本机项目目录(实时 watcher) | `/data/RAG/bak/<author>/` 备份归档 |
| 新文档可检索延迟 | 分钟级(实时) | **最长 1 小时**(备份已提频到每小时) |
| 检索范围 | 自己的 | 全部接入者的 |
| 单点 | 无 | 0.10/内网不可达则无法检索 |
| 资源 | 每机 ~2GB | 仅服务器 ~4GB,客户端零开销 |

## 中心实例部署记录(192.168.0.10)

约束:生产服务器(load 常 6/8,禅道在跑)——一切限速;8765 被 php 占用——**用 8766**;
Python 3.11——uv 装独立 3.12,零系统改动。

| 组件 | 部署形态 |
|---|---|
| 代码 | `git archive` → `~/rag-kb`(无 .git) |
| 依赖 | uv + python 3.12,**清华镜像**(直连 pypi 慢 20 倍) |
| 模型 | 本机 tar-over-ssh 传输 BGE-M3(3.9G,内网几分钟) |
| Qdrant | docker `qdrant/qdrant:v1.10.1`(镜像从本机 docker save/load,Hub 直连超时),卷 `/data/RAG/qdrant`,绑 127.0.0.1:6333,`--restart unless-stopped` |
| MCP 服务 | systemd `kb-central-mcp`(开机自启、失败 10s 重启、Nice=5、**PYTHONUNBUFFERED=1**) |
| 鉴权 | `KB_MCP_TOKEN`(~/.kb/central.env,600);绑 0.0.0.0:8766 |
| watch | `/data/RAG/bak/pingtao.cao/Glow/Projects`,first_subdir,`*/docs/*`,**--author pingtao.cao** |
| 索引 | 服务内置每日增量(启动 5min 首跑),OMP_NUM_THREADS=4 + Nice 限速 |

**实测验证**:无 token 401 / 带 token 200(内网不可匿名搜);kb_status 正常;
限速下 load 无明显抬升。

### 踩坑(此环境特有)

- **★ bat 文件必须纯 ASCII(2026-09-28 切流当天实证)**:cmd.exe 按系统代码页
  (GBK)解析批处理,而编辑工具写入的是 UTF-8——中文注释被错误解码后
  **破坏了 `if exist` 块的语法**,DISABLE_LOCAL_KB 停用标记检查从未执行
  (现象:切流杀掉本机实例后,任务计划的"失败重启"每分钟把它拉起来,
  且日志里 0 条拦截记录;手动跑 bat 报"不是内部或外部命令"却继续起服务)。
  修法:两个 bat 注释全部改英文,文件头注明 ASCII-only 约束(`ee385fa`)。
  与之前的"LF 换行破坏 goto"是同族问题——bat 对编码和换行都敏感。
- **stdout 管道缓冲阻塞**:tqdm 进度条 + 未设 PYTHONUNBUFFERED → 4KB 缓冲
  打满后**整个索引进程卡死**(CPU 空闲、库零增长、无报错)。后台运行带
  进度条的进程必须 unbuffered。
- 0.10 出网差:pypi 用清华镜像;docker 镜像从本机 save/load 传输。
- `ssh "cmd"` 内嵌 heredoc 会因多层引号解释静默失败——unit 文件先落本地再 scp。
- **任务计划的 RestartCount 与"杀进程"语义**:kill 本机实例后任务会按
  1 分钟间隔自动重启它(哪怕 bat 正常退出),停用必须靠脚本内标记文件
  静默退出,而不是指望杀进程一劳永逸。

## 客户端接入中心模式(任一台机器)

```bash
# Claude Code(全局)
claude mcp remove kb-local -s user   # 如已有本机实例配置
claude mcp add --transport http kb-local http://192.168.0.10:8766/mcp \
  --header "Authorization: Bearer <TOKEN>" -s user
# Codex
codex mcp add kb-local --url http://192.168.0.10:8766/mcp \
  --env KB_MCP_TOKEN=<TOKEN>   # bearer_token_env_var 形式按版本文档配置
```

TOKEN 在 0.10 的 `~/.kb/central.env`(管理员掌握,发给接入者)。

## 加人流程(两段式,已全脚本化)

**归档布局已统一为 `/data/RAG/bak/<author>/<项目>/docs/...`**(2026-09-29 起,
backup.py 改为镜像相对 watch 根的路径,不再镜像本机盘符与中间目录层——
此前 `Glow/Projects` 层来自个人本机路径,每人不一样,中心 watch 无法模板化)。

1. **同事侧**(一条命令):`scripts/setup_contributor.ps1 -Author <禅道账号>`
   完成本机全部配置,并在桌面生成 `kb-provision-request.txt`(账号+ssh 公钥)
2. **管理员侧**(一条命令):收到 request 文件后跑
   `scripts/provision_server.ps1 -RequestFile <文件>`,自动完成:
   服务器账号存在性检查 → `usermod -aG rag`(sudo)→ 公钥注入 authorized_keys
   (幂等)→ 中心加 watch `/data/RAG/bak/<账号>` → 重启中心服务
3. 回复同事"好了",对方跑一次 `backup.py --dry-run` 验证

> 服务器账号本身不存在时脚本会明确报错(创建账号需真实运维,不自动做)。
> 安全边界:管理员的 ssh 私钥不落到同事机器——所以服务器侧操作集中由
> 管理员执行,同事只提供公钥申请文件。

## 切流记录(2026-09-28 晚,已执行)

中心实例检索质量验证通过后,本机切至中心模式:

1. 全局 Claude Code 配置 → `http://192.168.0.10:8766/mcp`(带 token header);
   Codex → 同 URL + `bearer_token_env_var = "KB_MCP_TOKEN"`(用户环境变量已 setx)
2. 项目 `.mcp.json` 同步指向中心
3. **本机实例停用**:创建 `~/.kb/DISABLE_LOCAL_KB` 标记文件,两个启动脚本
   首行检测到即静默退出——免 admin 禁用任务计划,删掉标记文件即恢复本机模式
4. 本机 MCP 服务与 watcher 进程已停(释放 ~3GB 内存);
   **备份任务保留且已提频到每小时**(中心模式的数据源,不能停)
5. **索引提速神来之笔**:0.10 空 cache 首嵌需 ~11 小时(限速下),把本机
   23877 条 embedding_cache 直接导入 0.10(同一批文件 chunk 的 content_hash
   相同),253 篇 2 分钟跑完

回滚到单人模式:`del ~/.kb/DISABLE_LOCAL_KB` → 重启(或跑 start_mcp_http.vbs)
→ `claude mcp remove/add` 指回 `http://127.0.0.1:8765/mcp`。
