# Windows 新用户接入实测记录(2026-09-29,hailili)

首次端到端实测"新同事从零接入 kb-local 多人模式",全链路验收通过
(她的会话内 `kb_search` 命中 `[hailili] demo/docs/2026-09-29-测试文档.md score=1.000`)。
本文沉淀实测中暴露的 5 个坑与根治方法——全部已修入脚本,后续接入不再踩。

## 测试环境与方法

- 同一台 Windows 机器新建本地用户 hailili 模拟新同事(Windows 用户目录隔离,
  等效一台干净新机:~/.claude、~/.codex、~/.kb、npm 全局全部独立)
- 前置:NPM_CONFIG_PREFIX=C:\tools\npm-global(机器级)——claude/codex 命令
  所有用户零安装可用
- 服务器侧:0.10 上 hailili 原为 influxdb 服务账号(uid 1008)

## 五个坑与根治

### 坑 1:UAC 空密码死锁

- 现象:setup 脚本注册备份任务弹 UAC,要求输 Lenovo(管理员)密码;
  该账户无密码,怎么输都过不去
- 根因:Windows 安全策略禁止空密码账户为**其他用户**的 UAC 弹窗授权
  (空密码只允许本机交互登录)
- 根治:注册"以当前用户身份运行"的计划任务**根本不需要管理员**
  (实测 schtasks /create 非提权 exit 0)。setup_contributor.ps1 已去掉
  Start-Process -Verb RunAs,失败时打印手动命令兜底(`ddd3ff5`)

### 坑 2:服务器账号是 nologin 服务账号

- 现象:backup.py ssh 报 "This account is currently not available",
  重试 3 次全败(公钥认证其实已通过)
- 根因:0.10 上的 hailili shell 为 /usr/sbin/nologin(influxdb 服务账号),
  认证后被 shell 拒绝
- 根治:usermod -s /bin/bash。provision_server.ps1 已加 shell 检查,
  发现 nologin/false 自动修复(`本日提交`)

### 坑 3:watch 配置未写入(docs=0)

- 现象:backup 输出 docs=0,测试文档没被收集
- 排障:`uv run kb watch list` → 空则手动补 watch add(注意 ProjectRoot
  用实际路径)
- 启示:安装脚本的每个环节都应可独立重跑验证;接入文档把
  watch list 检查写入标准排障步骤

### 坑 4:PowerShell 执行策略禁跑 claude

- 现象:新用户 PowerShell 里 `claude` 报"禁止运行脚本"
- 根因:npm 全局包生成 .ps1/.cmd 双入口,PowerShell 优先解析 .ps1,
  默认 ExecutionPolicy=Restricted 禁止;老用户碰巧设过策略所以没遇到
- 根治:删除公共目录的 *.ps1 入口保留 .cmd(批处理不受策略限制),
  全用户一次生效、不动安全策略。注意 npm 重装/更新会再生成 .ps1,
  届时再删;或用户自行 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`

### 坑 5:watcher 不感知新加的监控目录(最隐蔽)

- 现象:备份成功、归档文件已在服务器,但中心库 hailili docs=0、搜索不中
- 根因(两层):①watcher 仅在**启动时**读一次 watch_dirs 清单,provision
  新加的作者目录对运行中的 watcher 不可见;②watcher 只监听**新事件**、
  不补扫,已落盘的文件永远不会被它索引
- 根治:provision_server.ps1 改为同时重启 watcher 与 MCP 两个服务
  (`c02f039`)——MCP 服务启动 5 分钟后的增量首跑按最新清单收齐存量
- 运维启示:加 watch 后必须重启 watcher;日常兜底靠 MCP 内建每日增量

### 附:新用户 Claude Code 直连官方 API 报 403

- 中转站配置在管理员用户目录里,新用户天然没有 → 报 403
- 根治:`scripts/setup_ai_env.ps1`(管理员准备 settings+token 两个文件
  与脚本同目录发给新用户,其本机一条命令装好中转站+kb-local MCP)

## 接入流程终版(实测跑通后的顺序)

1. 管理员:发三样东西——kb-local 仓库、AI 环境包(脚本+settings+token)、
   (可选)接入卡
2. 新用户:仓库里跑 `setup_contributor.ps1 -Author <禅道账号> -ProjectRoot <项目根>`
   → 桌面生成 request 文件发回
3. 管理员:`provision_server.ps1 -RequestFile <文件>`
   (账号/nologin/rag 组/公钥/中心 watch/双服务重启全自动)
4. 新用户:`backup.py --dry-run` 验证;跑 `setup_ai_env.ps1` 配 AI 环境
5. 新用户会话里问一句 kb_search——验收
